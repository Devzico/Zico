# 🐾 Zeko Social

منصة اجتماعية حقيقية (Node.js + Express + Socket.io) تعمل على أي استضافة تدعم Node،
وتكون كل البيانات (الحسابات، المنشورات، المحادثات، الصور، الفيديوهات) **مشتركة بين كل
زوار الموقع** — وليست محفوظة في متصفح شخص واحد فقط كما كانت النسخة السابقة.

## المميزات

- تسجيل حساب حقيقي بكلمة مرور مشفّرة (bcrypt) + جلسات JWT
- خلاصة منشورات (نص، صور، فيديو، صوت، PDF، استطلاعات رأي، تحذير محتوى CW، رؤية عام/متابعون/خاص)
- إعجاب، إعادة نشر، رد، تعديل، حذف، تسجيل صوتي مباشر من المتصفح
- ملف شخصي: صورة شخصية وغلاف حقيقيان يُرفعان ويُخزَّنان على الخادم، بايو، متابعة، حظر
- بحث عن مستخدمين ومنشورات وهاشتاجات
- إشعارات (إعجاب، رد، إعادة نشر، رسائل، متابعة)
- **دردشة لحظية حقيقية عبر Socket.io**: رسائل نصية وملفات، تفاعل بإيموجي، رد على رسالة،
  حذف رسالة (لدى الجميع أو لديك فقط)، حظر مستخدم، مؤشر الكتابة، حالة الاتصال (متصل الآن)
- إيموجي مخصص قابل للرفع
- حماية أساسية: تحديد عدد محاولات تسجيل الدخول، رؤوس أمان HTTP

## هيكل المشروع

```
zeko-social/
├── server.js              نقطة انطلاق الخادم (Express + Socket.io)
├── db.js                   قاعدة بيانات JSON بسيطة على القرص (data/db.json)
├── utils.js                دوال مساعدة مشتركة
├── middleware/
│   ├── auth.js              توثيق JWT
│   ├── upload.js             رفع الملفات (multer)
│   └── security.js           تحديد المحاولات + رؤوس أمان
├── lib/chatLogic.js        منطق الدردشة المشترك بين REST وSocket.io
├── routes/                 auth, accounts, posts, chats, notifications, emojis, search
├── public/                 الواجهة الأمامية (HTML/CSS/JS تعمل مباشرة من المتصفح)
│   ├── index.html
│   ├── css/style.css
│   └── js/                  ملفات منفصلة: state, api, auth, posts, profile, chat...
├── uploads/                 الصور والفيديوهات المرفوعة (تُنشأ تلقائيًا)
└── data/db.json             قاعدة البيانات (تُنشأ تلقائيًا عند أول تشغيل)
```

## التشغيل محليًا

```bash
npm install
cp .env.example .env
# عدّل JWT_SECRET في .env إلى نص عشوائي طويل وسري
npm start
```

ثم افتح `http://localhost:3000`.

## الرفع على استضافة حقيقية

يعمل المشروع على أي استضافة تدعم Node.js مع **تخزين قرص دائم (persistent disk)**،
لأن البيانات والملفات المرفوعة تُخزَّن في `data/` و`uploads/`. أمثلة:

### Railway / Render / Fly.io
1. ادفع المشروع لمستودع GitHub.
2. أنشئ خدمة Node جديدة واربطها بالمستودع.
3. أضف متغيرات البيئة: `JWT_SECRET` (قيمة عشوائية طويلة)، `PORT` (عادة تحدده المنصة تلقائيًا).
4. تأكد من تفعيل **Persistent Volume/Disk** وربطه بمجلدي `data` و`uploads` (وإلا
   ستُفقد البيانات عند كل إعادة نشر).
5. أمر البناء: `npm install` — أمر التشغيل: `npm start`.

### VPS عادي (Ubuntu مثلاً)
```bash
git clone <رابط مستودعك>
cd zeko-social
npm install
cp .env.example .env   # وعدّل القيم
npm install -g pm2
pm2 start server.js --name zeko-social
pm2 save
```
ثم اضبط Nginx كـ reverse proxy أمام المنفذ (تأكد من تفعيل دعم WebSocket لـ Socket.io):
```nginx
location / {
    proxy_pass http://localhost:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
}
```

### استضافة مشتركة (cPanel مع دعم Node.js Selector)
ارفع الملفات، حدد `server.js` كملف تشغيل، وتأكد من أن المضيف يدعم WebSocket
(بعض الاستضافات المشتركة الرخيصة لا تدعمه، وحينها ستعمل الدردشة برسائل غير فورية
عبر تحديث الصفحة بدلاً من اللحظية الكاملة).

## ملاحظات مهمة

- **النسخ الاحتياطي**: انسخ مجلدي `data/` و`uploads/` بشكل دوري — هما كل بيانات موقعك.
- **الأمان**: غيّر `JWT_SECRET` قبل النشر الفعلي، ولا ترفع ملف `.env` لمستودع عام.
- **حجم الملفات**: الحد الافتراضي 50 ميجابايت لكل ملف، يمكن تعديله عبر `MAX_UPLOAD_MB` في `.env`.
- إذا كبر عدد المستخدمين كثيرًا مستقبلًا، يمكن استبدال `db.js` بقاعدة بيانات حقيقية
  (PostgreSQL/MongoDB) دون تغيير باقي الكود، لأن كل الوصول للبيانات يمر من خلاله فقط.
